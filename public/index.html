About this take-home POC design requirements · non-functional requirements · how it was built · notes for reviewers

Design requirements

  • Send one prompt to multiple LLMs in parallel and present a combined view.
  • Stream responses live with per-model telemetry (TTFT, latency, tokens, cost).
  • Reveal which model DigitalOcean's Auto-Router chose for this prompt.
  • Provide an Advisor that synthesizes consensus, divergences, and a recommendation — reducing model FOMO.
  • Answer for this prompt, not abstract benchmark scores.

Non-functional requirements

  • Performance: parallel fan-out; SSE streaming keeps first-token latency low; the UI never blocks.
  • Reliability: per-model timeouts + partial-failure isolation; graceful 403 (tier-locked) and 404 (removed); 429 retry with backoff.
  • Security: the DO token lives server-side only (App Platform secret) — never in the repo or browser; request/response size caps.
  • Cost & scale: per-IP rate limits, per-run cost bounds, and a daily token budget guard, sized under the workspace's DO quota.
  • Observability: structured JSON logs, request/trace IDs, per-model + retry spans, and a privacy-safe run audit (no prompt text).
  • Configurability: env-driven providers; the model catalog changes without code.
  • Accessibility & responsive: keyboard/focus-visible, aria-live, light/dark, reduced-motion, single-column on mobile.

How it was built — key decisions

  • One Node/Express service serving the static UI + API (same-origin → no CORS).
  • OpenAI-compatible provider adapter against the verified DO endpoint — one code path for every model.
  • Parallel fan-out + SSE streaming (not polling/sequential): wall-time = slowest model, with live fill.
  • Reasoning capture: chain-of-thought (reasoning_content) rendered for reasoning models.
  • Advisor is a model, not rules — it reads for semantic consensus; streamed on a fast moderator so it feels instant.
  • Anti-abuse + budget guard, 429 resilience, and mock mode with no token.
  • Tests: 13 unit/integration (node:test), a real-DO smoke contract check, and an interactive UX mockup (design/ux-mockup.html).

Notes for reviewers — where I'd go deep in a follow-up

  • Scale the guardrails: the in-memory rate/budget limiter is correct for a single instance; production moves it to a shared store (Redis) and adds per-caller auth + quotas.
  • Productize the router: the direct FOMO fix is routing-as-a-service — an OpenAI-compatible gateway that picks the best model per prompt, with ModelArena as its visible face (see ROADMAP.md).
  • Make the Advisor a judge: add evals + an automated scorer that ranks models on this prompt, so the advice is measurable, not just reasoned.
  • Cost at scale: use the calculator above — the real customer question is “is the expensive model worth it at volume?”
  • Observability depth: drop OTel exporters + spend dashboards on top of the audit trail we already emit.
  • Honest gaps, called out: no multi-tenant auth, in-memory audit, single-instance limits — all deliberate PoC scoping, documented in DESIGN.md.
